# Unity 2D판 · Unreal 고품질 3D판 제작 및 배포 검토

검토일: 2026-11-04 (Asia/Seoul). 사용자 요청에 따라 기존 프로젝트와 배포를 보존하면서 두 엔진의 별도 배포판을 만드는 방향을 기록한다. 후속 요청으로 공통 데이터 내보내기·진행 코어·Unreal 런타임/UI·성전 개발용 장면 생성기·호스트 빌드/패키지 도구를 소스로 구현했다. 실제 상태와 실행 절차는 [구현 기록](GospelImplementation.md)을 따른다. 이 문서의 클라우드 호스팅과 최종 품질 제작은 제안/후속 범위이며, 실제 Unreal 빌드·화면·공개 URL 완료 보고서가 아니다.

## 확인한 접근 범위

`first_game`으로 지칭한 저장소는 [ka8877/firstgame](https://github.com/ka8877/firstgame)이며 연결된 GitHub 도구로 읽기 접근했다. 검토 기준은 `808d8d1e1eeed908d8925398f80c7173653ef364`다. 별도 Unity 클라우드 인스턴스나 그 안의 미커밋 파일에는 연결하지 않았다. 현재 이 채팅에는 `unreal_yesu`의 Linux 클라우드가 연결돼 있고 UE/Windows/GPU 빌드 호스트는 연결돼 있지 않다.

검토한 파일과 Git blob 식별자는 [소스 검토 기록](Evidence/firstgame-source-review-20261104.json)에 남긴다. Unity 저장소·카드게임·공개 사이트에는 쓰기 작업을 하지 않았다.

## 두 버전의 제품 계약

| 항목 | Unity판 | Unreal판 |
|---|---|---|
| 표현 | 2D/HD-2D 인물·다층 배경, 웹 접근성 | 입체 인물·공간, 조명·카메라·애니메이션·사운드 연출 |
| 공유할 내용 | 사건 순서, NPC 역할, 목표·본문 ID, 발견·진행 규칙 | 같은 이야기와 규칙을 Unreal에서 구현 |
| 별도로 제작할 것 | 기존 Unity 화면과 조작 | 3D 캐릭터·환경·애니메이션·UI·BGM·믹싱·장면 연출 |
| 배포 | 기존 Web 빌드 URL 유지 | Windows 패키지 + GPU 스트리밍 체험 URL 제안 |
| 저장 | 기존 Unity 슬롯·진행 보존 | 새 콘텐츠 버전·별도 저장 슬롯. 크로스 세이브는 미구현 |

Unity판은 현재 회화형 인물과 3D 필드를 결합한 HD-2D 구현이다. 사용자가 부르는 2D판의 범주로 보되, 이 검토에서 Unity 화면이나 렌더러를 변경하지 않는다. 두 버전은 같은 화면을 해상도만 바꾸는 제품이 아니라, 같은 사건을 서로 다른 매체 표현으로 경험하는 제품이다.

## 실제 Unity 스토리와 게임 루프

현재 Unity판은 예수님을 주인공으로 **탄생 → 열두 살 성전 방문 → 성인 요단강 세례**를 다룬다. 전 생애 완성이 아니라 초반 이야기다.

- `GospelChronicleCatalog.cs`: 23목표(탄생11·성전7·세례5), 사건·NPC·본문 연결. `festival-courtyard`, `teachers-circle`, `parents-reunite`, `nazareth-return` 같은 안정 ID를 보존한다.
- `GospelStorybookCatalog.cs`: 탄생 서막51화면, 장면·장소·시점·음악 역할·안정 음성 키.
- `GospelChronicle.cs`: 이동 → 도착 → NPC 대화 → 이야기 완료 → 본문 발견 → 다음 목표. 19본문의 발견형 성경책과 현재/완료 목표 기록.
- `GospelConversations.cs`와 `GospelNpcCatalog.cs`: 직접 인용·요약·극화 구분, 진행을 건너뛰지 않는 곁가지 학습 대화.
- `GospelBelongings.cs`와 `GospelPilgrimageSave.cs`: 소지품·등잔 상태 및 기존 저장 원본/좌표 공간 보존.

본문은 해당 사건의 마지막 이야기 화면을 마칠 때 한 번만 발견한다. 성경책을 열거나 음성을 재생하는 행위로 진행하지 않는다. 미발견 면은 제목·장절·본문을 숨긴다. 직접 인용의 문구와 `성경전서 개역한글판 · 대한성서공회` 출처를 보존하고, 요약과 극화를 구분한다.

현재 Unreal의 누가복음5 여행자·두 선택·세 결과·기억 회귀는 다른 이야기다. 이를 공유 캠페인에 자동으로 섞지 않는다. 기존 원본·저장은 별도로 보존하고 새로운 복음서 콘텐츠 버전을 추가한다. 이전 `GospelJourney.md`/`GospelChronology.md`의 초기7본문 설명보다 실제 최신 Core 카탈로그를 우선한다.

## 공유 데이터와 재사용 경계

첫 구현은 검토한 커밋에서 스토리 데이터만 추출하는 것부터 시작한다. 엔진 독립 manifest/JSON에 콘텐츠 버전, 원본 저장소/커밋/파일, 사건·NPC·본문 ID, 순서·조건, 텍스트 종류·장절·출처, 음악 역할·음성 키를 기록한다. Unity C# 런타임이나 씬을 Unreal에 복사하지 않는다. Unreal Editor importer가 검증된 데이터를 C++ DataAsset로 만들고 패키지에 Cook한다. 런타임에는 GitHub나 원본 C#이 필요 없어야 한다.

동기화는 검토한 커밋 단위로 수행하고, Unity 개발 브랜치의 변화를 자동으로 공개 Unreal판에 적용하지 않는다. 사건 순서·본문·해금 조건의 동일성을 공통 콘텐츠 검사로 확인하되, 좌표·카메라·애니메이션·사용자 설정은 엔진별로 유지한다.

Unity에는 Lost Crypt 샘플 등 Unity Companion License 자산이 포함돼 있다. 해당 자산을 Unreal로 복사하지 않는다. 자체 이야기·규칙과 출처가 확인된 텍스트를 공유하고, 3D 자산과 음악은 Unreal 배포에 적합한 권리·출처를 확인해 별도로 제작/선정한다. 오디오의 역할·전환 규칙을 재사용하는 것과 기존 음원 파일을 그대로 재배포하는 것은 별도 판단이다.

## Unreal 품질 제작 순서

기존 C++ 상태·저장 오류 처리, 입력·카메라·상호작용, Editor 생성·검증·패키징 도구는 재사용할 기반이다. 현재 이야기 전이는 C++에도 고정돼 있어 JSON 변경만으로 새 캠페인이 동작하지 않는다. 새 진행 어댑터·검증·저장 버전을 함께 구현해야 한다.

현재 세 인물은 정적 메시이고 보행·표정 리그가 없다. 실제 BGM도 없고 합성 환경음4개는 임시다. 현 자산을 고품질 완성판으로 제공하지 않는다. 사용자는 2026-11-04 미술 방향으로 **영화 같은 실사·반실사 3D**를 명시적으로 선택했다. 이는 제작 방향의 확정이며 현재 자산의 품질 승인이나 완성 보고가 아니다.

확정한 표현 기준은 자연스러운 인체 비율과 연령 구분, 피부·머리카락·린넨 의상의 재질, 설득력 있는 석재·지면·식생, 영화적인 조명·카메라와 절제된 UI다. 실제 골격 보행·정지·시선·대화 동작, 장면에 맞춘 BGM·공간음까지 함께 검수한다. 인물의 가까운 대화 화면과 전신 이동 화면을 모두 실제 Unreal에서 확인하고, 성경 본문과 극화의 구분을 유지한다. 예수님의 외모는 창작적 재현이다.

1. 기존 열두 살 유월절 여정에서 **성전 뜰 도착 → 선생들과의 만남 → 부모와 재회 → 본문 발견/일지 → 저장·이어하기**를 첫 대표 구간으로 선정한다. 3–5분은 제작 범위 제안이며 측정된 플레이 시간이 아니다. 기존 갈릴리 선택·회귀를 필수로 넣지 않는다.
2. 한 장소와 주요 인물에 집중한다. 열두 살 인물과 성인 인물을 구분하고, 실제 골격·자연스러운 이동/정지·시선/대화 동작·카메라·의상 표현을 제작한다. 예수님의 외모는 창작적 재현이다.
3. 환경의 재질·지형·식생·빛·대기·공간음, 장면별 실제 BGM과 전환/음량, 한국어 자막·대화·책·일지 UI를 함께 완성한다. 엔진 기능을 켰다는 이유로 시각 품질이 달성됐다고 판단하지 않는다.
4. 실제 Unreal GPU 화면에서 인물의 근접 외관·움직임, 텍스트 가독성, 음악/소리, 입력·충돌·저장/복귀, 프레임 시간을 확인한다. Unity와 같은 사건을 비교할 수 있는 실제 캡처를 남긴다.
5. 대표 구간의 품질과 테스트 URL 사용성을 확인한 뒤 탄생 서막과 요단강으로 범위를 확장한다. 현재 51개 Unity 화면을 기계적으로 51개 3D 컷신으로 옮기는 것을 목표로 삼지 않는다.

## 현재 배포 방식 평가

현 `SyncAndPlay.ps1`은 테스터 PC에 소스를 내려받아 Editor 컴파일·에셋 생성·검사·패키징을 수행한다. `server.mjs`는 `127.0.0.1`/단일 제어 세션/빈 ICE 서버 목록을 사용한다. 개발자 로컬 재현에는 유효하지만 사용자가 원하는 “URL만 열어 새 버전 확인”에는 적합하지 않다.

Unreal의 브라우저 체험은 게임을 PC/클라우드 GPU에서 실행하고 WebRTC로 영상·소리·입력을 주고받는 Pixel Streaming으로 구성한다. GitHub Pages는 안내·다운로드 링크를 제공할 수 있지만 이 Unreal 패키지를 실행하는 서버를 대신하지 않는다. [Epic 개요](https://dev.epicgames.com/documentation/unreal-engine/pixel-streaming-in-unreal-engine), [호스팅·네트워크](https://dev.epicgames.com/documentation/en-us/unreal-engine/hosting-and-networking-guide-for-pixel-streaming-in-unreal-engine).

제안 파이프라인:

`GitHub 후보 커밋 → UE 설치 빌드 호스트 → 검증된 Windows 패키지 → GPU 스트리밍 → 고정 preview URL → 실제 확인한 빌드만 공개 URL에 반영`

빌드 호스트는 보유 RTX5080 Windows PC를 연결하거나 별도 UE 빌드 환경을 마련한다. 일반 GitHub Windows runner에는 이 프로젝트의 UE/GPU가 준비돼 있지 않다. 스트리밍용 GPU 인스턴스와 Editor/빌드 환경도 별개다. URL 배포만으로 클라우드 에이전트의 Editor 화면 편집·GPU 검수가 가능해지는 것은 아니다.

| 선택 | 적합한 용도 | 운영 조건 |
|---|---|---|
| 보유 PC의 로컬 Pixel Streaming | 개발 중 직접 확인, 초기 미디어 검증 | PC가 켜져 있어야 함. 현재는 같은 PC에서만 접근. 외부 URL은 인증·HTTPS/WSS·ICE/STUN/TURN 및 외부망 검증 추가 |
| 관리형 Pixel Streaming | URL로 테스트·시연, 개인 PC를 꺼도 되는 체험판 | GPU/서비스 요금, 지역·시작 대기·지연·동시 세션·저장 정책 확인 필요 |
| 완성된 Windows 패키지 다운로드 | 고품질 정식 PC 배포, 서버비 없는 로컬 플레이 | 사용자 GPU 필요. 테스터에게 UE/Visual Studio 설치는 필요 없음 |

사용자의 편의 목표에는 **전용 빌드 호스트 + 관리형 Pixel Streaming 테스트 URL**을 우선 권한다. 이후 같은 패키지를 Windows 다운로드판으로도 배포한다. 현재 로컬 updater는 개발용 대안으로 유지한다.

한국에서의 지연을 고려해 [Vagon Streams 서울/도쿄 지역](https://docs.vagon.io/streams/guides/worldwide-coverage)을 첫 검증 후보로 검토했다. 공식 안내는 [Windows 패키지 업로드·Stream Link 생성](https://docs.vagon.io/streams/unreal-engine-pixel-streaming)을 제공한다. 실제 이 프로젝트의 **UE5.8/PixelStreaming2 호환성·지역 가용성·음성/입력·지연**은 작은 패키지로 먼저 검증해야 한다. 아직 서비스를 선정·연결·결제하지 않았다.

[공식 요금](https://vagon.io/streams/pricing)에는 사용 시간 외 앱 유지·저장 등의 비용 항목이 있으므로 “접속할 때만 과금”으로 단정하지 않는다. 대안 [Eagle](https://docs.eagle3dstreaming.com/wiki/plugin-compatibility)은 PixelStreaming2를 명시하고 [버전별/최신 앱 URL](https://docs.eagle3dstreaming.com/wiki/apps-and-versions)을 제공하지만 한국 접속 지연과 실제 엔진 호환성은 역시 검증 대상이다.

## 배포 구현 전 해결할 조건

- UE 빌드·화면 검증 호스트 연결 및 작은 패키지의 실제 PixelStreaming2 영상·소리·입력 확인.
- 고정 preview/public 경로와 불변 build ID, 실패 시 이전 정상 패키지로 복귀, 테스트 중 자동 공개 전환 금지.
- 사용자별 세션·저장 분리. 현 고정 저장 슬롯/단일 UserDir를 여러 사용자에게 공유하지 않는다. 초기 체험판의 새 세션 초기화와 정식 이어하기 정책을 구분한다. Unity와의 저장 동기화는 별도 후속 기능이다.
- 브라우저의 실제 플레이, 오디오 시작, 새로고침/재연결, 저장·이어하기, 외부망 연결과 동시 접속 제한 검증. URL HTTP 응답만으로 완료 처리하지 않는다.

## 조사와 후속 구현의 실제 수행 범위

GitHub의 고정 소스·스토리 계약, 로컬 Unreal 구현과 배포 스크립트, 서비스 공식 문서를 조사했다. 이어서 원본 C# 카탈로그를 실제 컴파일·평가해 공통 스토리 데이터를 만들고, 별도 진행/저장/Unreal UI 및 개발용 성전 생성기와 빌드·배포 준비 도구를 구현했다. 소스 검사의 실제 결과와 미실행 항목은 [구현 기록](GospelImplementation.md)에 분리한다. 최종 캐릭터/BGM 제작·실제 Unity/Unreal 화면 실행·Windows 패키지 빌드·외부 URL 배포는 아직 수행하지 않았다. 기존 실행기와 공개 버전은 유지했다.
